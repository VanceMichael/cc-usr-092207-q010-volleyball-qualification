# 女排锦标赛晋级计算

三个小组人数不同（5/5/4），却要取各组前两名和**成绩最好的两个第三名**进入八强。
本仓库把这一流程建模为「不可覆盖赛果 → 当届规则派生 → 带时间发布 → 开赛锁定」，
使任一历史版本都能重算、核对和解释。

## 模型分层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 当届规则 | `src/rules.js` | 积分（3:0/3:1 得 3 分、3:2 得 2/1）、组内排名顺序、第三名归一化、排签口径、固定交叉对阵、锁定条款。规则是数据，换届只改配置 |
| 赛果记录 | `src/records.js` | 只追加的事件台账：赛果（逐局比分/弃权/阵容异议/裁判确认）、改判、处罚、撤销处罚、抽签、开赛；任何更正都新增记录，旧记录原样保留 |
| 排名 | `src/standings.js` | 积分→胜场→C 值（局分比）→Z 值（得分比）→相互间（两队）→平分小循环（三队+）→抽签 |
| 晋级 | `src/qualification.js` | 组内顺位；第三名跨组归一化比较（5 队组剔除与垫底队的对赛）；八强 1–8 号签；固定交叉 QF 对阵 |
| 发布 | `src/publication.js` | 带发布时间的不可变快照；补录/改判/撤罚后重算发布新版；已开赛的四分之一决赛锁定，只标记冲突不自动改写 |
| 解释 | `src/explain.js` | 任意版本中某队为何晋级/落签；两版差异影响面；球队原始记录簿 |

## 记录类型（`contracts/events.schema.json`）

- `matchResult`：每场比赛的逐局比分；弃权 canonical 为 0:3（每局 0:25）；
  阵容异议（提出方、成立/驳回，成立时被异议方记弃权）；裁判与记分确认。
- `correction`：补录 / 裁判复核 / 申诉改判，引用原比赛整体替换生效赛果，
  不能改对阵双方；原记录留在 `history`。
- `penalty` / `penaltyReversal`：处罚扣分与申诉撤销，撤销引用原处罚。
- `drawOutcome`：平分且规则指标用尽时的抽签，技术代表确认。
- `kickoff`：比赛开赛，开赛后对阵锁定。

台账按追加顺序重放；记录上的 `ts` 是事实发生时间，**赛后补录允许早于登记时刻**。

## 示例数据（全部虚构）

`scripts/build-fixture.mjs` 由紧凑赛果表生成：

- `fixtures/tournament.json`：14 队 5/5/4 分组与比赛索引；
- `fixtures/events.json`：完整事件流；
- `fixtures/publications.json`：v1、v2 两个发布快照。

剧本：v1 中云港、梅浦取两个第三名，蓝湾与静海归一化战绩完全相同由抽签定 1/2 号，
QF4（静海 vs 云港）开赛；随后沙溪-鹤城 3:1 误记经复核改判 3:2、江洲申诉撤销扣分，
v2 重算后鹤城升入八强、梅浦出局，QF1–QF3 重排而 QF4 已开赛锁定，
系统同时标出三类仲裁冲突（锁死对阵与重算不符、云港双重占场、鹤城被占席）。

## 本地校验

```bash
npm test            # 24 个 node:test 用例
npm run build:fixture  # 由赛果表重新生成 fixtures
```

测试覆盖：比分合法性（25 分净胜 2 分、决胜局 15 分）、弃权与异议、
改判不可篡改、重复/悬空引用拒绝、积分与各级平分、第三名归一化、
快照可再生、版本不可覆盖、开赛锁定与冲突、任意版本解释与球队记录簿。

契约文件在 `contracts/`（JSON Schema）。仓库不保存账号、密钥、连接串或真实身份信息。
