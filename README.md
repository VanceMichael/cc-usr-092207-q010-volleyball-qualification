# 女排锦标赛晋级计算

计算女排锦标赛小组排名、跨组晋级和淘汰赛签位。三个小组规模不同(5/5/4),各组前两名与成绩最好的两个小组第三晋级八强,八强按小组赛战绩排一至八号签后进行固定交叉对阵。

## 处理链路

每场局分、逐局得分、弃权、阵容异议和裁判确认先形成**不可覆盖的赛果记录**,再依照当届规则逐级产生组内顺位、跨组比较、签位与对阵:

1. **赛果记录**(`src/records.js`):账本只增不改。补录是某场比赛的第一条记录;申诉改判是同一 `match_id` 的新记录并以 `supersedes` 指向被取代的记录;处罚扣分是独立记录。待确认记录留档但不参与计算;球队可用 `teamRecords` 核对自己的全部原始记录。
2. **当届规则**(`src/rules.js`):积分办法(3:0/3:1 得 3 分,3:2 得 2/1 分)、组内顺位比较链(积分→胜场→胜负局比率→得失分比率→相互间成绩→抽签)、跨组第三名比较链与排签链(跨组无相互比赛,不得用相互间成绩)、晋级名额与固定对阵表。
3. **组内顺位**(`src/standings.js`):按比较链逐级细分同分队,每对相邻名次都记录是哪一级准则分出的;比率按交叉相乘比较,避免浮点误差。
4. **晋级与签位**(`src/advancement.js`):各组前二直接晋级,三个小组第三按跨组比较链取前二;八队按小组赛战绩排签,落入固定对阵(1-8、4-5、3-6、2-7)。
5. **版本与锁定**(`src/versions.js`):每次发布生成带发布时间、规则编号、纳入记录编号的不可变版本。补录、处罚、改判发布后产生新版本:未开赛的淘汰赛对阵可以重排,已开赛的签位必须锁定;锁定对阵与新计算结果不一致时记入 `conflicts`,交竞赛委员会裁定。`publicView` 提供带发布时间的公众榜单。
6. **解释**(`src/explain.js`):面对任一历史版本,`explainTeam` 说明某队为何晋级、为何落在该签位;`explainDiff` 说明一次修正影响了谁、由哪些记录引起。

## 示例数据

`fixtures/tournament.json` 为 14 队(三组 5/5/4)的完整小组赛果,队伍均为虚构,含一场弃权与一次阵容异议。示例中 A 组第三与 B 组第三积分、胜场、胜负局比率完全相同,由得失分比率分出先后。

## 本地校验与演示

```sh
npm test          # 运行全部测试(记录、排名、晋级、版本锁定、解释)
node scripts/demo.mjs   # 演示:首版发布 → 处罚扣分重排 → 改判遇开赛锁定
```

`contracts/domain.schema.json` 规定共享资料结构,`fixtures/domain.json` 保存不含真实个人信息的示例。仓库不保存账号、密钥、连接串或真实身份信息。
